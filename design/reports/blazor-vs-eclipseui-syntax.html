Razor 指令速查（11 项）

按 Blazor 组件（.razor）语境整理。在 MVC 视图 / Razor Pages（.cshtml）中，@page 表示该文件是 Razor Page，@inherits 常写 CustomRazorPage<TModel>，imports 文件是 _ViewImports.cshtml。

指令作用典型写法可放 _Imports.razorEclipseUI 对应
@page把组件声明为可直接用 URL 访问的可路由组件；路由参数可填同名 [Parameter] 属性@page "/counter"否，逐组件无路由概念；模板内写触发 EUI009，窗口/页面切换由应用宿主承担
@using导入 C# 命名空间；对 .razor 还决定哪些组件在作用域内。imports 文件里的 @using 只作用于 .razor，不作用于 .cs@using BlazorSample.Components是K22/K23 已定（待 S6 实施 / D85）：模板内写 @using {Ns}，内置控件也须 @using EclipseUI.Elements；生成代码保留 using {Ns};，并按导入命名空间决定标签可见性
@inject从 DI 容器取服务，生成可直接使用的服务属性@inject IJSRuntime JS是无 DI 指令；依赖由构造函数 / 参数传入
@inherits指定生成类的基类（与 code-behind partial 不同，用于一组组件共享基类逻辑）@inherits MyComponentBase是基类继承写在 .cs partial 类声明上
@implements让生成的组件类实现指定接口，典型用于资源释放@implements IAsyncDisposable是接口列表写在 .cs partial 类声明上
@attribute给生成的组件类加 .NET 特性；也可替代 @page 提供常量路由模板@attribute [Authorize]
@attribute [Route(Constants.CounterRoute)]		是特性写在 .cs partial 类上
@namespace设置生成类的命名空间；放在 imports 文件时按目录树设置根命名空间（就近优先）@namespace MyApp.Components是由项目根命名空间与 .cs 类声明决定
@layout为带 @page 的可路由组件指定布局组件，减少重复外壳@layout MainLayout是，对同目录及子目录生效无布局概念；外壳就是元素树本身
@rendermode指定 Blazor Web App 的渲染位置与交互性（.NET 8+）：InteractiveServer / InteractiveWebAssembly / InteractiveAuto；不指定即静态 SSR@rendermode InteractiveServer
<Dialog @rendermode="InteractiveServer" />		否，逐组件无 SSR / CSR 之分，只有桌面自绘一条路径
@preservewhitespace控制标记中的空白是否保留到渲染输出；默认 false，会移除元素 / RenderFragment 首尾及代码块前后的空白@preservewhitespace true是空白规范化是 spec/01 固定行为，无开关
@typeparam为生成的组件类声明泛型类型参数，支持 where 约束@typeparam TItem where TItem : IEntity否，逐组件泛型标签暂缓（K19），当前写法落 EUI100

拼写提醒：官方文档写作 @preservewhitespace（whitespace 全小写），不是 @preserveWhitespace。_Imports.razor 口径按 Blazor 组件文档：@page / @rendermode / @typeparam 必须逐组件声明。

同一段界面的写法

Blazor · Counter.razor

<p>Count: @count</p>
<button @onclick="Increment">+1</button>
<input @bind="name" />

@code {
    int count = 0;
    string name = "";
    void Increment() => count++;
}

EclipseUI · Counter.ui + Counter.cs

<TextBlock Text={$"Count: {Vm.Count}"} />
<Button OnClick={Increment} Text="+1" />
<TextBox @bind-Text={Vm.Name} />

// Counter.cs：partial 类中声明 Vm、Increment

三个「看着一样、其实不同」的点

  1. @ 的权限。Blazor 里它同时是表达式前缀、指令前缀、指令属性前缀；EclipseUI 里它只管 @bind- 与 @if/@foreach，动态值一律 {...}。因此 Razor 的 @()、@@、@{} 在这里都没有对应物。
  2. 内容的生命周期。Blazor 的 RenderFragment 随组件重渲染重算；EclipseUI 的默认内容与具名插槽是 build-once 元素列表，不随父组件 Render() 重算（K10）。
  3. 近乎同名的巧合。@bind-Value + ValueChanged（EventCallback，回调整体参与重渲染）与 @bind-P + {P}Changed（Action<T>，build-once 赋值 + 差异才推送并 Invalidate()）形态相似，运行语义不同。
一句话概括：EclipseUI 表面像「XAML 的属性语法 + Razor 的 C# 表达式」，但 @ 的语义窄得多，运行时是固定元素树 + 表达式重算，而不是渲染树 diff；Blazor 的路由、DI、泛型组件、CSS isolation、属性展开等 Web 侧能力，在 .ui 里要么没有对应物，要么仍是保留语法位。
