## 1. 语言模型

### 控件模板扩展（2026-11-14）

显式声明 `@template T` 的文件采用控件模板工厂模式，T 必须为导入的 TemplatedControl 类型。
文件名标识 `ControlTemplate<T>`，根元素标识每个实例的视觉根；强类型 `Owner` 指向宿主。
普通 `.ui` 不受此扩展影响。`Part="名称"` 提供实例内部件身份，`Ref` 保持代码字段语义。
控件模板中的 StyledProperty 赋值进入可覆盖的 skin 层；完整实现范围及样式语法见
[design/28](../design/28-lookless-controls.md)。

### 1.1 一个文件 = 一个类 = 一个根类型

- 每个 .ui 有且仅有一个根标签；文件名为生成类名，必须为合法 C# 标识符（EUI013）。
- @namespace 必填；可无 code-behind 和 @code。有 code-behind 时要求同名顶层 partial 类，命名空间一致。
- 生成类直接继承根标签解析到的 CLR 类型，InitializeUi 初始化 this。显式 code-behind 基类必须匹配根类型；初始化/更新保留名冲突报 EUI045。
- 根类型可为任何合法可继承 UiObject 派生类型；sealed 与根继承环报 EUI064。根层文本/结构块不代替根标签。
- Window 与普通类型共用解析、属性和内容规则。Window 非 Element，不能赋给 Element 内容（EUI060）；它的 Content 是允许为空或接收一个元素/动态块的单项成员。
- 生成过程不额外创建根包装对象。Ref、样式及附加属性指向实际控件实例。

### 1.2 code-behind 与状态

- 状态载体 = 同名 `.cs` partial 类 **与** 模板内 `@code` 成员，二者合并进同一个 partial 类（K21/K23 ④）：
  单文件模板可以只有 `@code`、没有 `.cs`；两者都没有也合法（纯展示组件，spec/02 §2.7）。
- 模板作者写**普通类型**：`int`、`string`、`List<T>`、数组、字典、LINQ 结果、普通类/record/struct。
  不需要 `[UiState]`/`[UiObservable]`/`[UiComputed]`，不需要 `INotifyPropertyChanged`，
  集合不需要 `INotifyCollectionChanged`/`ObservableCollection<T>`（spec/03 §1.1）。
- 模板直接读写普通成员：`P`、`Tasks.Count`、`GetName()`；没有 `.Value` 重写、没有可观察路径要求。
- `Signal<T>` 是遗留运行时类型，**不是模板反应式机制**：模板必须显式写 `Count.Value`；
  写入 `.Value` 不会自动刷新，需要显式 `Invalidate()`（spec/03 §4.6）。
- 非 UI 事件引起的状态变化（后台线程、`await` 续体、定时器、直接改集合/对象）必须显式调用
  `Invalidate()`；控件事件与组件回调的包装会自动失效所属组件（spec/03 §9）。
- 模板不声明局部变量、类型参数；类成员与命名空间导入写在 `@code` / `@using` 里（K21/K22），
  复杂逻辑放 code-behind 或 `@code` 成员，模板只写 C# 表达式。

### 1.3 编译期与运行期分工

| 阶段 | 做什么 | 不做什么 |
|---|---|---|
| 编译期 | 词法/句法/语义分析、目录解析、字面量转换、生成 C# | 不执行用户程序集、不执行用户转换器、不反射运行时、不做依赖分析 |
| 运行期 | 构造保留元素树、首次求值、失效队列、块刷新、重算动态表达式、属性引擎失效、布局与绘制 | 不解析 `.ui`、不做通用元素 diff、不按字符串查成员、不观察任何对象 |

模板不是"字符串拼 UI"的外壳，而是编译单元：每个动态位置在编译期已知目标元素、目标属性与首次求值顺序；
运行期按**组件渲染**重算，不按路径/信号订阅。

### 1.4 当前约束

1. 每个 .ui 对应一个类和一个根类型，状态成员可写在 @code 或同名 partial .cs 中。
2. 根标签初始化当前实例；Window 非 Element，由内容类型限制嵌入，不设专用标签分支。
3. 状态是普通 CLR 类型；Invalidate/Render 重算编译期已知动态槽，没有依赖追踪。
4. 单向赋值及绑定按成员能力选择，ui/C# 来源不改变行为。
5. 结构变化由 if/foreach/switch 协调器处理；Key相等且item身份相同才复用。
6. 事件与void委托在初始化时安装，处理后自动使所属对象失效。
7. 普通外部状态变化显式失效；安装UI同步上下文后，宿主按批排空续体并整体失效真实子树。
8. Class/Style/附加属性作用于实际Element；根默认值与调用方local值有明确优先级。
9. 标识符大小写敏感，using alias可消歧；表达式沿用C#语义，错误映射原文件。
10. 构建/块/树资源必须有确定释放路径；不保留独立组件包装及兼容机制。

## 2. 词法

### 2.1 源文件

- 扩展名 `.ui`，以 `AdditionalFiles` 进入编译；编码按 Roslyn 文本读取（UTF-8）。
- 文件名（去扩展名）必须是合法 C# 标识符；否则 `EUI013`。
- 换行支持 LF/CRLF；`#line` 使用 1 基行/列坐标（span 形态见 spec/02 §2.4）。
- 一个文件只包含一个文档；文件级只有注释、空白、根层 `@namespace`/`@using`/`@code` 指令和一个根元素（§3.1/§3.2）。

### 2.2 两种扫描模式

- **文本模式**：标签之外。识别文本、`{expr}`、`@directive`、`<`、`}`、`<!-- -->`。
- **标记模式**：`<` 之后到 `>` / `/>` 之间。识别标签名、属性名、`=`、双引号字符串、`{expr}`；
  空白（含换行）被忽略。
- 模式切换只由 `<`、`>`、`/>` 驱动；表达式与指令内部的 `<`/`>` 不切换模式
  （lambda 的 `=>`、泛型参数不会截断标签）。

### 2.3 名字

规范只承认 ASCII 标识符：

```ebnf
ident      ::= [A-Za-z_][A-Za-z0-9_]*
tag-name   ::= ident
attr-base  ::= ident ( "." ident )?
attr-name  ::= attr-base ( ":" ident )?
bind-attr  ::= "@bind-" attr-base
```

- 标签名是单段短名：`Button`、`TextBlock`。**不带命名空间、不带泛型实参**；
  泛型标签按 K19 暂缓实现、不排期（`EUI030` 为保留位诊断，当前写法落 `EUI100`）。
- 属性名支持 `Owner.Name` 形状仅为附加属性预留（G4，如 `Grid.Row`）；
  附加属性实现前报保留诊断 `EUI031`，不退化为 `EUI002`。
- 末尾 `:ident` 是旧修饰符：`bind` / `value` **已移除**（K27）：`P:bind`/`P:value` 报 `EUI046`（Error），
  提示改写为 `@bind-P={...}` / `P={...}`；`EUI043` 停用且保持停用；
  其它修饰符按未知属性处理 `EUI002`。
- `@bind-P` 是双向绑定的**独立属性形态**：只出现在标记模式的属性名位置，
  `@bind-` 是字面前缀，`P` 是 `attr-base`；它不是指令，不参与 `@if`/`@foreach` 的 `@name` 解析。
  - 大小写敏感：`@bind-Checked` 合法，`@bind-checked` 解析到未知属性（`EUI002`/`EUI040`）。
  - `@bind-P:bind` 或 `@bind- P`（带空白）是语法错误 `EUI100`。
  - 不得绑定保留属性 `Key`/`Ref`/`Class`/`Style`、事件 `On*` 或 `[UiContent]`/`[UiSlot]` 参数 → `EUI040`。
- 名字**大小写敏感**；标签冲突由目录报 `EUI016`。
  标签解析作用域最初按 K22 定为「只在模板 `@using` 导入的命名空间内解析，内置控件无豁免」
  （D85 ✅；未导入报 `EUI001` + 缺失 `@using` 建议，全局命名空间里的类型始终可见，同名多解读 `EUI016`）。
  **K33（D111，2026-11-11）修订**：`@namespace` 声明的命名空间及其外层链**不需要 `@using`**——
  按 C# 简单名查找顺序，内层先命中就独占（外层与 `@using` 的同名候选直接不可见，不报 `EUI016`）。
  链外命名空间的口径不变；未声明 `@namespace` 时不做隐式可见（那时只应有一条 `EUI055`）。
- `Key` / `Ref` / `Class` / `Style` 是保留属性名，控件不得声明同名属性（design/14 §14.4.2）。

实现说明：当前 `Lexer` 接受比规范更宽的名字字符集（含 Unicode 字母与 `.`/`:`/`-` 开头），
这只是扫描器的宽松性，不是语言 API；最终由分析器按目录报 `EUI001`/`EUI002`。
规范不保证这些名字的行为。

### 2.4 记号

| 记号 | 含义 |
|---|---|
| `<` / `</` / `>` / `/>` | 标签开/闭/自闭合 |
| `=` | 属性赋值；两侧可有空白 |
| `"..."` | 属性字面量（仅双引号） |
| `{...}` | C# 表达式（§2.6） |
| `@bind-属性名` | 双向绑定属性（仅标记模式属性位置，§2.3） |
| `@name` / `@name(...)` | 指令（§2.7） |
| `<!-- ... -->` | 注释（§2.9，与 `@* *@` 等价） |
| `@* ... *@` | 注释（§2.9，K23/K26） |

- 标签/属性之间允许任意空白与换行；`<StackPanel>`、`<StackPanel >`、
  `<StackPanel\n  Gap="8"\n>` 等价。
- 属性必须有 `=` 和值；`<Button disabled>` 是语法错误 `EUI100`，不是布尔属性简写。

### 2.5 属性字面量

- 仅双引号字符串；单引号不是属性定界符。
- 字面量是**原始文本**：不解析 XML 实体（`&amp;` 原样是 `&amp;`），不做空白折叠，可跨行。
- 词法上 `\` 使其后的一个字符不参与"结束引号"判定；**但值保留原始字符，不做反转义**：
  `\"` 在值中是 `\` 和 `"` 两个字符。需要精确的引号/反斜杠时，用 C# 表达式：`P={"a\"b"}`。
- 值是否为空串合法由目标属性决定；`Label=""` 合法。
- **字面量还是表达式由 token 决定，不由内容决定**：带引号的 `P="{x}"` 是字符串字面量 `{x}`，不是表达式。

### 2.6 表达式

`{ csharp-expression }`：

- 从 `{` 开始按平衡大括号捕获，配对由**C# 片段扫描器**完成（D11，`CSharpSnippet`）：
  普通字符串、verbatim `@"..."`、raw `"""..."""`、插值字符串 `$"..."`（含插值洞与格式说明符）、
  字符字面量 `'c'`、行/块注释里的 `{`/`}` 都**不计数**。
- 可以包含嵌套 `{}`、lambda 块体、`=>`、泛型 `<...>`；`>` 不会截断表达式。
- 表达式必须是 **C# 表达式**，不是语句/声明。需要复杂逻辑时调用 code-behind 方法或在 code-behind 里准备好值。
- **不提供插值格式说明符**（语言规则，不是扫描限制）：文本里的 `{price:F2}` 就是表达式 `price:F2`，
  不是合法 C#。要格式化就写 `{price.ToString("F2")}`。
- 空表达式 `{}`、不完整表达式不在词法层报错，交给生成代码的 C# 编译错误（经 `#line` 指回 `.ui`）。
- 文本/指令里的表达式不做 trim；C# 自行忽略外围空白。
- 表达式**原样输出**：生成器不做 `Signal<T>` 裸名重写、不做语义模型改写；
  需要 `.Value` 时由作者显式写（spec/03 §4.6）。

### 2.7 指令

- `@name` 后可选 `(...)`；括号按平衡圆括号捕获（同 §2.6 的 C# 片段扫描：字符串/注释/插值感知）；
  指令名只含字母/数字/`_`。
- 指令全集（K21–K31，✅ S6 + K31）：`@if (...)`、`@foreach (...)`、`@switch (...)`、`@code { ... }`、
  `@using Ns`、`@using Alias = Ns.Type`；`else` / `else if (...)` 是不带 `@` 的续接（紧接前一分支的 `}`，
  由词法一次性识别）。
- `@using` 只接受两种形态，**同一行内写完**：命名空间导入与类型别名。`@using (...)`、`@using static`、
  `@using Ns;`（尾分号）、泛型别名、`A.B = ...`（别名必须是单个标识符）都在词法层报 `EUI100` 专属消息，
  且错误 token 吞掉整行——绝不把残余字符交回文本模式（否则会报成与写法无关的 `EUI006`）。
  别名语法与语义见 §4.17。
- `@switch` 的块体形态见 §4.16；`EUI008` 随其转实现而停用，停用码保持停用。
- `@bind-属性名` 只在标记模式属性位置识别，不是指令；文本模式写 `@bind` 仍是未知指令 `EUI009`。
- 其它 `@name`：`EUI009`（收窄到明确拒绝清单：`@for`/`@while`/`@do` 给 `@foreach` 改写建议，K24；
  `@page`/`@rendermode` 等 Web/类形状指令按 K23 ② 永久不提供）。
- `@` 没有文本转义；要输出字面 `@`，写 `{"@"}`。`@` 后跟 `{`（代码语句块）按 K28 不采纳，报 `EUI100`。
- 文档顶层（根层）除唯一元素外，还允许 `@code` / `@using` / 注释（K21/K22）；
  其它指令出现在根层仍是 `EUI012`（元素根数量）或 `EUI100`。
  孤立出现的裸 `else`（前面没有 `@if` 分支）不是续接，按普通文本处理并落 `EUI006`。

### 2.8 文本与特殊字符

文本模式下的特殊字符：

| 字符 | 行为 | 写字的办法 |
|---|---|---|
| `<` | 开始标签 | `{"<"}` 或整段用表达式 |
| `{` | 开始表达式 | `{"{"}` |
| `}` | 结束块；不在块内则 `EUI100` | `{"}"}` |
| `@` | 开始指令 | `{"@"}` |
| `>`、`&`、`=`、引号 | 普通文本 | 直接写 |

- 没有 CDATA、没有 XML 实体、没有 HTML 标签白名单；任何 `<` 都按标签解析。
- 文本节点可跨行；原始换行/缩进按 §2.10 规范化。
- 文本里不能直接写 `<` 做比较；表达式 `{a < b ? "x" : "y"}` 必须在 `{...}` 内。

### 2.9 注释

- 两种等价注释（K26）：`<!-- ... -->` 与 `@* ... *@`，都只在文本模式识别；不能写在标签内部。
  两套并存、`<!-- -->` **不设弃用期**（语义未改义，`@* *@` 是新增语法）。
- 注释不嵌套；内容丢弃，不进入 AST，不是 trivia；相邻文本会拼成同一文本节点
  （`a<!--c-->b` → `ab`）。
- **未闭合的两种注释都报 `EUI100`**，且词法推进到文件尾（不得静默吞尾、也不得停在原地导致解析死循环；
  D12 / D88）。
- 注释不参与 pretty-printer（当前没有 pretty-printer）。

### 2.10 空白与规范化

- 标记模式内空白忽略；属性之间、`=` 两侧、`/>` 前均可换行。
- 文本内容在**每一层**（文档、元素、`@if`、`@foreach`）规范化：
  1. 若该层的第一个节点是文本节点，且其第一个段是静态段，则 `TrimStart`；
  2. 若该层的最后一个节点是文本节点，且其最后一个段是静态段，则 `TrimEnd`；
  3. 纯空白文本节点整体丢弃（含表达式或非空白字符的文本节点不丢）。
- 中间空白（包括内部换行与缩进）保留；多行动态文本的缩进会进入字符串，
  需要精确排版时用表达式或 code-behind 方法。
- 规范化的结果是：模板的缩进不会渲染成前导/尾随空格；这与 XAML/JSX 直觉一致。
- 注释移除发生在规范化之前；`a<!--c-->b` 的两个文本段按中间内容处理，不会被首尾 trim 影响。

## 3. 句法

### 3.1 EBNF

```ebnf
document      ::= { using-directive | code-block | node } EOF
node          ::= element | text-run | if-block | foreach-block | switch-block

element       ::= "<" tag-name attribute* ( "/>" | ">" node* "</" tag-name ">" )
attribute     ::= ( attr-name | bind-attr ) "=" ( string | expression )
attr-base     ::= ident ( "." ident )?
attr-name     ::= attr-base ( ":" ident )?
bind-attr     ::= "@bind-" attr-base
text-run      ::= ( text-char | expression )+

if-block      ::= "@if" "(" csharp-expression ")" "{" node* "}"
                 { "else" "if" "(" csharp-expression ")" "{" node* "}" }
                 [ "else" "{" node* "}" ]
foreach-block ::= "@foreach" "(" "var" ident "in" csharp-expression ")" "{" node* "}"
switch-block  ::= "@switch" "(" csharp-expression ")" "{" section* "}"
section       ::= ( "case" csharp-expression ":" | "default" ":" ) node* "break" ";"

using-directive ::= "@using" namespace
                 |  "@using" ident "=" type-name      // K31：类型别名（同时是标签别名）
type-name      ::= [ "global::" ] ident ( "." ident )*
code-block      ::= "@code" "{" csharp-member* "}"

expression    ::= "{" csharp-expression "}"
string        ::= '"' raw-char* '"'
```

说明：

- 顶层（`document`）允许 `@using` / `@code` / 注释与任意节点；`@code`/`@using` 不进入元素内容（K21/K22）。
- `using-directive` 的别名形态（K31）左侧必须是**单个标识符**（不能是 `A.B`），右侧是类型名（可带 `global::`），
  且整条指令写在同一行——别名用于在模板内给重名控件起短名，见 §4.17。
- `else` / `else if` 是 `@if` 的续接，**不带 `@`**，必须紧接前一分支的 `}`（K23 ③）。
- `switch-block` 的 `case`/`default` 头、`break;` 与分支体文本都是裸文本形态，
  由解析器按 C# 片段扫描 + 行首标记拆开（见 §4.16）。
- `text-char` 排除 `<`、`{`、`}`、`@`；注释在词法层删除，不进入 `node*`。
- 结束标签必须与开始标签同名（区分大小写）；自闭合 `<X />` 等价于 `<X></X>`。
- `attribute` 必须有值；不允许只写属性名。
- `bind-attr` 的值**必须**是 `expression`：`@bind-P="true"` 报 `EUI037`（不是字面量转换）。
- 同一元素上 `@bind-P` 与 `P=` 同时出现 → `EUI033`（同一目标重复赋值）；
  完全相同的属性名重复 → `EUI025`。
- 根层（`document`）在去掉注释/空白后必须恰好是一个 `element`，另允许顶层 `@code`/`@using` 指令节点；
  `text-run` 或控制流块出现在根层是 `EUI006`，0 个或多个元素根是 `EUI012`（K21/K22，D85/D86 ✅）。
- `node*` 的合法组合由内容模型进一步限制（§4.9），句法层先接受再语义拒绝。
- `@inherits`/`@model`/`@page`/`@rendermode` 等按 K23 ② 永久不提供；`@for`/`@while`/`@do` 按 K24 不提供；
  未知 `@` 指令是 `EUI009`，`@{}` 语句块按 K28 报 `EUI100`。
- 泛型标签（`DataGrid<Order>`）、附加属性（`Grid.Row`）不在当前句法内；附加属性按 G4 保留，
  泛型标签按 K19 暂缓、不排期（§4.15）。
  插槽标签（`<Slot>`/`<ContentSlot>`）是**句法级保留名**：解析器特判成槽节点（§4.15），
  目录把占用这两个名字注册的控件报 `EUI031` 保留冲突并隐藏该标签。

### 3.3 内容模型的句法后果

块（`@if`/`@foreach`/`@switch`）的内容**永远按"元素容器"处理**，即使外层是 `Text`/`TextRuns` 模型；因此：

- `@if`/`@foreach`/`@switch` 里不能直接写裸文本或 `{expr}` 文本，必须先包一个 `TextBlock`；
- 在 `Text`/`TextRuns` 模型里写块直接 `EUI006`；
- "条件文本"不能用 `<TextBlock>@if ...</TextBlock>`：把 `@if` 放在容器层控制整个 `TextBlock`，
  或在 `TextBlock` 内写文本表达式（复杂逻辑放 code-behind 方法）。

## 4. 语义

### 4.1 模板类与作用域

- 生成代码的类壳、命名与顺序见 [spec/02](./02-generated-code-contract.md) §3–§5。
- 表达式作用域就是 C# 可见性；没有名字重写，也没有依赖分析：

| 位置 | 可见名字 | 求值时机 |
|---|---|---|
| 根元素/根属性/根文本 | code-behind 实例成员（`this` 隐式）、同命名空间类型、全限定类型 | 初始化首次；每次所属对象 `Render` 重算 |
| `@if` 内容 | 同上；不能声明局部变量 | 分支构造时首次；分支存活期间每次所属作用域刷新重跑 |
| `@if` 条件 | 同上 | 初始化首次；每次块刷新重算 |
| `@foreach` 集合 | 同上 | 每次块刷新重新求值并枚举 |
| `@foreach` item | item 变量 + 外层 item 变量（嵌套）+ code-behind 实例成员 | 条目构造时首次；复用条目每次刷新重跑 |
| `Key={expr}` | item 变量 + code-behind 实例成员 | 每次枚举每个 item 求值 |
| 控件事件/void委托属性 | 同上 | 初始化一次（build-once） |

- 模板本身不声明局部变量、方法、类型参数；类成员写在 code-behind `.cs` partial 或根层 `@code` 块（K23 ④，✅ S6）。
  `@code` 成员与 code-behind 成员在同一条生成链上一视同仁（`EUI045` 只拦与生成保留名冲突的成员），
  表达式仍只写在模板位置。
- 没有"可观察路径"概念：`Vm.Count`、`GetName()`、`Tasks.Where(...)` 都是普通 C# 表达式。
- item 变量遮蔽遵循 C#：item 变量遮蔽同名 code-behind 成员；规范建议不要制造这种遮蔽。
- 事件处理器里的读取发生在触发时（§4.13）；事件体不参与任何渲染重算。

### 4.2 标签与属性解析

所有 ui/C# 类型通过同一符号目录解析，按成员能力处理：保留属性 → 路由事件 → StyledProperty/普通可写 CLR 属性 → 声明的附加属性 → 未知。

- 名字大小写敏感。标签遵循命名空间和 alias 查找；未知 EUI001、冲突 EUI016、不可用类型报告确定原因。
- 普通 public getter/setter 属性可赋值，无需 UiParameter。UiParameter 可声明 Required；内容和具名槽由 UiContent/UiSlot 描述。
- StyledProperty 赋值由属性引擎相等短路；plain CLR 属性相等保护下写 setter 并使目标失效。
- 路由事件按 OnEvent 解析；void 委托属性按真实签名包装；非 void 委托为普通值属性。
- 绑定按 StyledProperty 或匹配 PChanged 能力选择，不按控件来源分类。只读、内容、槽、事件及保留属性不可绑定。
- Class/Style/附加属性要求 Element 目标；Ref 赋实际实例；非 Element 内容宿主仍可用普通属性和内容成员。
- 默认内容/槽是初始化快照，先赋值再初始化目标。目录和诊断的完整规则见 spec/04。

### 4.3 赋值形态总表

| 写法 | 求值与行为 |
|---|---|
| P="literal" | 初始化一次，编译期转换 |
| P={expr} | 初始化和后续 Render 重算；内容参数内部为构建快照 |
| @bind-P={expr} | 首次源到目标，后续双向；目标须具备绑定能力 |
| OnE={handler} / void 委托属性 | 初始化安装一次；处理后使所属对象失效 |
| Key={expr} | foreach 枚举时计算条目身份 |
| Ref={field} | 初始化时赋实际实例；必须可写字段 |
| Class="a b" / Class={expr} | 初始及动态类集；模板类和使用点类合并 |
| Style="P: value;" | 静态内联 setter；表达式形式拒绝 |
| P:bind / P:value | 已移除，EUI046 |

### 4.4 单向赋值 `P={expr}`

初始化首次求值，之后在所属对象 Render 重算。StyledProperty 写公开 setter 并由属性系统短路；普通属性转换至目标类型、相等保护后写入并使目标 Invalidate。静态字面量只初始化一次。

参数与回调在目标 EnsureInitialized 前就位；根输入参数在 base.InitializeUi 前就位。Render 不重建静态对象。void 委托是事件式输入，只在初始化安装；表达式不进行依赖追踪，也不要求可观察路径。

同一目标同时出现 P 和 @bind-P，或文本与对应字符串属性重复写入，报 EUI033。表达式应无副作用；C# 类型错误经原文件映射报告。

### 4.5 双向绑定 `@bind-P={expr}`

目标按成员能力选择：可写StyledProperty生成UiBinding；普通可写属性要求PChanged回调（返回void、一个与P同类型参数）。内容、槽、事件、保留属性、附加属性不能绑定。未知名字EUI002，存在但能力不够EUI040。

源必须为类型匹配的可写左值：字段、可写属性、引用item的成员。方法调用、索引器、条件访问、只读/静态成员、值item成员以及属性返回struct的中间写入报EUI037；自绑定同样拒绝。不可静态判定的问题交C#经源映射报告。

首次方向源到目标；StyledProperty绑定订阅变更并用同步守卫防回环，普通属性绑定先安装回调再相等保护推送。目标动作改变值后回写源并失效声明绑定的对象。重复目标写入报EUI033。

初始化快照内容内部不建立双向绑定（EUI040），需要动态状态的内容应自身实现为独立ui/C#控件。完整运行时规则见spec/03 §8。

### 4.6 旧语法 `:bind` / `:value`（已移除，K27）

- `P:bind={expr}` / `P:value={expr}` **不再合法**：报 `EUI046`（Error），消息提示改写为
  `@bind-P={expr}` / `P={expr}`，并短路生成输出。
- `EUI043`（旧语法弃用告警）停用且保持停用（§8 规则 4）；测试与诊断快照零出现。
- 迁移：`:bind` → `@bind-P`；`:value` → `P=`；`Signal<T>` 字段 → 普通字段/属性（§附录 B.3）。

### 4.7 `Signal<T>` 与值上下文

- 表达式**不做任何重写**：模板写 `Count` 就读 `Count`，写 `Count.Value` 就读 `.Value`。
- `Signal<T>` 仍是运行时类型，但不是模板反应式机制：
  - 读取 `Count.Value` 不建立订阅；写入 `Count.Value = x` 不自动刷新；
  - 需要刷新时在写入后调用 `Invalidate()`；
  - 新代码建议用普通字段/属性，不用 `Signal<T>`。
- item 成员同样不重写：item 的普通属性直接读，item 的 `Signal<T>` 成员必须显式 `.Value`。
- 没有字符串/注释/同名局部变量的重写问题：生成器原样输出表达式（文本插值除外，§4.9）。

### 4.8 生命周期与资源

- EnsureInitialized 幂等构造静态内容与首次动态值；Render 只刷新动态槽、绑定与块。
- @code 与纯 C# 共用 OnInitialized、OnAttached、OnDetached、OnUpdating、OnUpdated、OnDispose。挂接指接入活跃宿主树，离线组树不触发；挂接父先子，摘除子先父。
- 普通子控件归实际内容树，根/块绑定资源分别登记到 UiObject.Track/BlockScope。
- 短命构建作用域在失败时清理尚未挂接对象，成功后不保留第二套子项表。
- Children.Remove/Clear 只摘除，允许重挂；Dispose 与 Unmount 统一摘除并释放，按子树和资源逆序完成清理且幂等。释放 HeadlessRoot 只结束宿主挂接，树仍归调用方。
- if 分支变化、foreach 身份变化/条目移除及块释放都会清理旧作用域与根实例。
- 不存在独立组件生命周期、挂载 API 或根转发。详见 spec/03。

### 4.9 文本与内容模型

内容模型由控件/组件声明（design/14 §14.4.4）：

| 模型 | 允许的子内容 | 生成目标 | 违规 |
|---|---|---|---|
| `None`（默认） | 无 | — | 任意子内容 `EUI006` |
| `Children` | 元素、嵌套块；纯空白文本忽略 | 目标 `.Add(Element)` | 非空白文本 / 非法结构 `EUI006` |
| `Text` | 文本段与 `{expr}` | 目标 `string` 属性（如 `Button.Label`） | 元素/块 `EUI006` |
| `TextRuns` | 文本段与 `{expr}` | `ITextContentHost.AddRun(string)`（`TextBlock`） | 元素/块 `EUI006` |

文本语义：

- 静态文本在 初始化时赋值：`Text` 模型合并所有静态段为一条字符串；
  `TextRuns` 模型把**连续静态段**合并为一个 `TextRun`（空段不生成），与 spec/02 §4.8.1 一致。
- 含 `{expr}` 的文本是**动态文本**，随所属作用域渲染重算：
  - `Text`：一个文本节点生成**一个完整插值串**，每次渲染重设整个目标值；
  - `TextRuns`：每个动态段 `AddRun("")` 创建一个空 `TextRun`，每次渲染只重设该 run 的 `Text`；
    静态段不受影响，不重新 `AddRun`。
- 集合内容变化不会自动触发：`{Tasks.Count}`、`@foreach` 都在组件 `Invalidate()` 后的渲染/刷新中
  重新求值；UI 事件内自动失效，非 UI 事件需显式调用（spec/03 §9）。
- 文本插值使用 C# `$"..."`：当前区域文化、`ToString()` 语义。`{expr}` 里**没有** `{expr:F2}` 这种格式说明符位置
  （格式说明符是 `$"..."` 内插值串的语法，不是模板语法）；要格式化写 `{price.ToString("F2")}` 或整段 `$"..."`（§2.6）。
- 文本里不能嵌套元素或块；`TextRuns` 也只接受文本段，需要多段不同样式等富文本能力时另设控件（G4）。
- **同一目标重复赋值是错误**：`Text` 模型下显式 `Label="..."` 和文本内容同时存在，
  或 `P={expr}` 与同一目标绑定同时存在，报 `EUI033`（文本 + 显式目标已实现，S2）。
- `Children` 模型中的纯空白文本在规范化后消失，不报 `EUI006`；非空白裸文本报错，必须包元素。
- 组件的默认内容参数（C4）按组件声明的 `[UiContent]` 模型处理；具名插槽见 §4.15（C6）——
  `<Slot>` 填充不参与默认内容的根计数，多根槽允许多次填充拼接。

### 4.10 `@if`

- 形式：`@if (condition) { ... }`，可选 `else if (condition) { ... }` 链，可带末端 `else { ... }`；
  `else`/`else if` 不带 `@`（K23 ③ / D87，✅ S6），由多分支 `ConditionalBlock` 承担。
  条件必须是 C# `bool` 表达式；非 `bool` 由 C# 通过 `#line` 报类型错误，没有专门的模板诊断。
  孤立 `else`（前面不是 `@if` 块）不参与续接，落成普通文本 → `EUI006`；`EUI009` 只留给其它未识别指令。
- 首次求值在 初始化时；之后每次所属作用域渲染通过 `ConditionalBlock.Refresh()` 重新求值。
  条件可包含方法调用/索引器/LINQ；没有"条件依赖"分析，也不需要。
- 条件在两次渲染间不变：分支内容保留，重跑分支的渲染动作（`BlockScope.RenderActions`）。
- 条件翻转：销毁旧分支（释放其作用域），构造新分支；新分支构造时完成首次求值。
- 空分支合法：不生成 `SetContent`，块保持空内容。
- 生成：`new ConditionalBlock()` → 挂父级 → `SetCondition(Func<bool>)` →
  `SetContent(Action<BlockScope>)` → 作用域登记 → 显式 `Refresh()`（spec/02 §4.9、spec/03 §6.2）。
  模板用 `AddRoot`/`AddRenderAction`/`AddDisposable` 登记，块创建并传入 `BlockScope`。
- 分支内容只允许元素与嵌套块；可以有多个根元素；分支切换丢失子树局部状态（焦点、滚动）。
- 在 item 模板内：条件可引用 item 与组件状态；条目复用/重建规则同 `@foreach`（§4.12）。
- 布局（✅ G3，台账 D77）：块协调器是**布局透明**节点。它仍留在元素树里（`FinalRect` 坐标链、
  命中测试、脏区跟踪都不变），但**不引入自己的间距与尺寸约束**：
  - 分支内的多个根元素按**最近布局祖先**的排布参数落位——即沿父链向上跳过其它布局透明节点后，
    第一个非透明 `StackPanelBase` 的 `Gap`；找不到则为 0。效果等价于把这些根元素直接摊进父容器。
  - 块的 `Padding` 恒为 0 参与布局，块自身的 `Gap`/`Padding` 属性值一律不参与
    （块是 `[UiIgnore]` 协调器，不在模板表面，作者无从设置）。
  - 块的期望尺寸 = 内容并集（宽 = 最大子宽，高 = 子高之和 + 上述 `Gap`），不含额外内边距。
  - **空块不占间距槽**：条件为假、或内容整体为零尺寸（含只含空块的嵌套块）时，块不贡献尺寸，
    父容器里它前后两个兄弟之间只有**一个** `Gap`。空块仍会被 arrange 到零尺寸矩形，
    避免 `FinalRect` 残留上一轮有内容时的位置。

### 4.11 `@foreach`

- 形式：`@foreach (var item in collection) { ... }`；**`var` 必写**，
  不支持 `T item in ...`、解构、`await foreach`。
  三种违规（类型化条目 / 解构 / 缺 `in` 或缺集合）给出针对性 `EUI100` 消息。
  头解析按**深度/字符串感知扫描**（tokenizer，2026-11-05）：集合内带引号的 `" in "`、
  括号内的 `in`（方法实参修饰符）不再被认为分隔符（旧正则实现的两处已知误切分）。
- `collection` 必须是 `IEnumerable<T>`（含 `T[]`、`List<T>`、`Dictionary<K,V>`、`HashSet<T>`、
  LINQ 结果、自定义实现、`ObservableCollection<T>`）；`T` 必须可推断。
- 值为 `null` 视为空集合，不构造条目，不报错；`null` 字面量因无法推断 `T` 报 `EUI007`。
- `IAsyncEnumerable<T>`、`IEnumerator<T>`、非泛型 `IEnumerable`、`dynamic` → `EUI007`。
- 集合表达式每次块刷新**重新求值并重新枚举**；不要求 `INotifyCollectionChanged`。
  `ObservableCollection<T>` 的变更事件不会自动触发渲染，仍需 `Invalidate()`。
- item 类型由 `IEnumerable<TItem>` 推断，生成 `ForEachBlock<TItem>`；item 变量只在块内可见。
- item 模板：
  - 可引用 item 成员、外层 item 变量（嵌套）、code-behind 实例成员；
    **不再禁止引用组件级状态**（v3 的 `EUI014` 移除）；
  - `Key` 可引用任意可读表达式（包括组件状态）；没有 v3 的 `EUI039`；Key 稳定性由作者负责；
  - `@bind-P` 源可以 rooted at item，也可以 rooted at 组件状态；没有 v3 的 `EUI042`；
  - `@bind-P={item.X}` 合法（item 可写属性双向）；
  - 嵌套 `@foreach`（S2）：内层集合可以是 item 成员、组件状态或任意 `IEnumerable<T>`；
    内层块登记在条目作用域，条目移除/重建时释放。
- item 模板可有多个根元素；`Key` 只允许出现在第一个元素根上，标识整个条目。
- 布局（✅ G3，台账 D77）：`ForEachBlock<T>` 与 `ConditionalBlock` 同为**布局透明**节点，规则见 §4.10 末条。
  条目间距因此等于最近布局祖先的 `Gap`（`TaskList` 的根 `Gap="4"` 即条目间距 4）；
  空集合的块不占间距槽，标题与后续兄弟之间只有一个 `Gap`。
- 空集合/单元素不特殊；`Key` 缺失时用 item 自身作为 key。
- 不建议在 `@foreach` 表达式里做重 LINQ；在 code-behind 缓存投影结果并显式失效（spec/03 §12.2）。

### 4.12 `Key` 与条目复用

- `Key={expr}` 只用于 `@foreach` 条目身份；非 item 模板根报 `EUI010`；字面量/空表达式报 `EUI010`。
- Key 可引用任意可读表达式（item 成员、组件状态、方法调用）；**没有** v3 的可观察性限制（`EUI039` 停用）。
  Key 变化会导致条目重建，稳定性由作者负责。
- 无 `Key` 时默认 key = item 自身（`ForEachBlock` 生成 `item => (object?)item`）。
- `Key` 表达式返回 `null` 时归一到一个共享空键；应避免 null，否则多个条目会互相复用。
- 重复 key 不报错；同 key 的条目按出现顺序复用（`Queue<Entry>`）；新出现的重复 key 新建条目。
- key 比较发生在对象装箱后；字典身份按 `Equals`/`GetHashCode`。
- **复用条件 = key 相等且 item 身份相等**（spec/03 §7.3）：
  - 值类型：`EqualityComparer<T>.Default.Equals(oldItem, newItem)`；
  - 引用类型：`ReferenceEquals(oldItem, newItem)`。
- key 相同 + item 相同：复用结构，重跑 `BlockScope.RenderActions`；条目内绑定保持。
- key 相同 + item 不同：释放旧 `BlockScope.Disposables`，**重建条目**；禁止闭包捕获旧 item。
- key 不同/新增：新建条目；旧条目未复用则释放。
- 条目复用时什么会重跑：

| 模板内容 | key 同 + item 同 | key 同 + item 不同 | key 不同/新增 |
|---|---|---|---|
| 元素结构 | 不重建 | **重建** | 重建 |
| 根层文本/`P={item.X}`（渲染动作） | 重跑渲染动作 | 重建时求值 | 新建时求值 |
| 根层 `@bind`（`UiBinding`/`PChanged`） | 保持原绑定，`Refresh()` 源 → 目标 | 重建并绑定新 item | 新建 |
| 事件处理器 | 捕获当前 item（同引用） | 重建并绑定新 item | 重建 |
| `@if (item.X)` | 每次刷新重算 | 重建 | 重建 |
| 嵌套 `@foreach` | 每次刷新重新枚举 | 重建 | 新建 |
| 组件参数推送 | 每次刷新推送 | 重建组件 | 新建 |

- 条目重建会丢失元素局部状态（焦点、滚动、动画）；Key 的职责是**重排身份**，不是"数据版本"。
  需要保留局部状态时，让 item 对象稳定、修改其属性后 `Invalidate()`，而不是替换 item 对象。
- item 为值类型时，同 Key 且值相等才复用；值变化会重建条目并丢失局部状态。
- `IEnumerable<object>` 中的值类型 item 每次枚举都会产生新装箱，按引用比较会每次重建；建议用具体 `T`。

### 4.13 事件

- **控件事件**：属性名 `On{EventName}`，对应 `{Name}Event` 的
  `public static readonly RoutedEvent` 字段（design/14 §14.4.3）。
  - 只接受 `{expression}`；字面量或 `:bind`/`@bind-` → `EUI004`/`EUI040`。
  - 处理器必须能转换为 `Action` 或 `Action<RoutedEventArgs>`；签名不匹配在**可静态判定**时由
    分析器报 `EUI024`（Error，✅ 2026-11-08/D82，落 `.ui` 属性值并短路生成输出），无法静态判定时
    静默、交回生成代码经 `#line` 由 C# 报错（spec/02 §2.4 规则 8 不重复报告）；判定口径见
    spec/02 §4.6.1 规则 7。两个委托类型的选择仍按表达式**语法形态**判定——tokenizer 切片
    （2026-11-05）用 Roslyn 解析替代正则。
  - **build-once**：初始化时 `el.AddHandler({Event}, 包装);`，不在渲染时重新注册。
  - 处理器表达式先转为委托局部 `h{N}`（类型为匹配到的 `Action`/`Action<RoutedEventArgs>`），
    包装在用户处理器**同步返回后**调用所属组件 `Invalidate()`：
    `var h0 = (Action)(() => AddTask()); el.AddHandler(Button.ClickEvent, () => { h0(); Invalidate(); });`。
  - 处理器抛异常时不执行自动 `Invalidate()`（异常向上传播）；组件保持当前 UI，直到下一次失效。
  - 事件字段必须声明在元素/组件类型上；静态宿主类不参与扫描（design/14 D11）。
    C1/C2 后控件事件表面共 9 个事件名：`OnClick`、`OnCheckedChanged` + 7 个输入/焦点事件
    （`OnPointerPressed/Released/Moved`、`OnKeyDown/Up`、`OnGotFocus/LostFocus`，C2 起声明在 `Element` 上）。
- **组件事件**（C4）：组件没有路由事件；委托类型参数即事件，属性名就是参数名
  （如 `OnClose`），不做 `On*` 前缀推断；同样只接受 `{expression}`。
  - build-once；处理器表达式先写入委托局部 `h{N}`，包装调用它后再 `Invalidate()` **父组件**（提供委托的一方）。
  - 委托必须返回 `void`，参数不得含 `ref`/`out`/`in`；否则 `EUI028`。
- 事件处理器里的读取在事件触发时发生；不建立订阅，不参与渲染重算。
- 事件处理器表达式**不参与任何分析**（没有依赖分析）；语法/类型错误由 C# 报。
- 事件处理器捕获 item：同 Key 同 item 复用安全；item 引用变化时条目重建。
- **异步处理器**：`async void` 在第一个 `await` 前返回，包装只失效一次；`await` 之后的状态变化
  必须显式 `Invalidate()`（spec/03 §9.3）。
- 事件名区分大小写；`Onclick` 是未知属性。

### 4.13.1 焦点状态与样式

`IsFocused`、`IsFocusWithin`、`IsFocusVisible` 是 FocusManager 维护的只读状态，不接受模板赋值或 @bind。对应平台伪类为 `:focus`、`:focus-within`、`:focus-visible`，无需 @states 注册；`:focus` 仍表示直接拥有焦点。

Element 的 `FocusVisualMode` 是可赋值、可样式化的枚举属性，取值 Auto / Outline / Control / None。样式目录同时提供 FocusRingWidth、FocusRingOffset、支持 theme() 的 FocusRingColor。文本编辑器默认使用自身边框，普通控件在键盘交互时显示外圈。Window 的 AlwaysShowFocusVisuals 参数配置本窗口的始终提示偏好。完整运行时与绘制契约见 [design/25](../design/25-focus-visuals.md)。

### 4.14 可复用 UI 类型

可复用类型可以用 C#、.ui 或二者的 partial 组合编写。文件根类型决定继承关系，类型本身决定属性、事件、内容与嵌入能力。

子标签构造顺序：new → 构建临时登记 → 属性/回调/Ref → 默认内容与具名槽 → EnsureInitialized → 加入声明的内容成员。

根标签初始化当前实例：普通输入/内容参数/槽先就位 → 基类初始化 → 本层模板默认属性与结构。StyledProperty 根默认值写 template 层，调用方 local 覆盖；类集内部在前、外部在后。

公开可写属性可直接使用；UiParameter(Required=true) 可声明必填（EUI027），UiContent/UiSlot 声明单/多项内容。绑定回调、插槽和资源规则对 ui 与 C# 完全相同，见 spec/03、spec/04。

具名插槽（C6，design/14 §14.6.3；生成形态 spec/02 §4.12.5）：

- 声明侧：组件的 `[UiSlot("名字")]` 属性。类型 `Element?` → 单根；`IReadOnlyList<Element>` → 多根；

  `[UiParameter]` 与 `[UiSlot]` → 参数胜出（`EUI028`，槽退出表面）；`[UiIgnore]` 胜出。
  基链继承：派生类同名属性**显式写了模板特性或 `[UiIgnore]`** 才算覆盖基类声明，
  否则基类的 `[UiSlot]` 继续生效（Roslyn 不把成员特性带进 override，偏差 D76）。
- 消费侧 `<Slot Name="...">...</Slot>`：只能作为组件标签**直属子级**；属性只接受字面量 `Name`；
  槽名必须是该组件 def 上声明的插槽；单根槽只接一个填充、一个填充只接一个根；错误 → `EUI022`。
- 多根槽可以多次填充，按源码顺序拼接（spec/02 §4.12.5）。
- 宿主侧 `<ContentSlot Name="..." />`：组件自身模板里拼接插槽内容的位置标记；只能是元素容器
  （Children 模型）的子级，不进 `@if`/`@foreach`（避免 build-once 内容被块重复重建拼装）、
  不可作根、不接受内容、自身模板同名只放置一次；错误 → `EUI022`。
- 解析口径：消费侧按父组件 def 的 `Slots`；宿主侧按 code-behind 类的 `[UiSlot]` 扫描
  （生成器传符号权威表；静态前端按目录显示名短名匹配 `doc.ClassName`，见偏差 D75）。

保留语法的统一规则：

- 不得把保留名用作普通控件/组件属性（控件作者侧 `EUI026`）；
- 使用保留语法时**必须**报"已保留、未实现"类诊断（`EUI031`/`EUI029`/`EUI030`；
  插槽错误用 `EUI022`，已实现），不得退化成 `EUI001`/`EUI002` 的拼写建议；
- `@bind-` 不是保留语法：它是双向绑定的语法形态；目标/源非法分别报 `EUI040`/`EUI037`，
  不得退化成 `EUI001`/`EUI002`；
- 实现保留语法时只增加状态，不改变已有语法的含义。

### 4.16 `@switch`（K23 ③ / K29 / K30）

形态：`@switch (value) { case CONST: … break; default: … break; }`。

- **分支体是完整内容模板**：元素、文本、嵌套 `@if`/`@foreach`/`@switch` 均可，与 `@if` 分支体能力对等（K29 ①）。
- **case 标签必须是编译期常量形态**（K29 ②）：字面量、`const` 成员、枚举成员、括号/正负号包裹的常量表达式。
  调用/运算等非常量形态在语法层拒绝（`EUI047`）；常量性由生成器探针判定，不可判定交 C#（经 `#line`）。
- **无贯穿语义**（K29 ③）：每个 `case`/`default` 是独立分支，等价隐式 `break`。
  因此 `case 1:` 紧跟 `case 2:` **不共享分支体**，这种写法报 `EUI100`（K30）——
  要么复制分支体，要么只用一个标签。
- **`break;` 必须结束该行**：可以跟在元素同一行的末尾，但该行其后只能是空白；
  非空 section 缺 `break;` 报 `EUI100`；嵌套块内的 `break` 报 `EUI100`（块内无「跳出」语义）。
- **`default` 至多一个**（重复报 `EUI100`）；缺 `default` 合法（无匹配时块为空，同 `@if` 全假）。
- **空 section 必须显式写 `break;`**：`case 1:` + `break;` 合法（渲染空内容）；`case 1:` 后直接跟下一个
  section 头报 `EUI100`（K30）。
- 匹配用 `EqualityComparer<T>.Default`；`T` 由生成器探针从 selector 推断，推断失败退化为 `object`。
- 生成形态见 spec/02 §4.17：`SwitchBlock<T>` + `SetSelector` / `AddCase` / `SetDefault`。

### 4.17 `@using Alias = Namespace.Type`（K31）

形态：`@using Btn = ThirdParty.Controls.Button`（整条一行，无分号）。

一条指令两个效果，缺一不可：

| 效果 | 落点 | 说明 |
|---|---|---|
| C# 类型别名 | 生成文件头 `using Btn = global::ThirdParty.Controls.Button;` | `@code` 成员与模板表达式里都能写 `Btn`（Blazor 口径）。目标一律补齐 `global::`，避免被生成类所在命名空间的同名类型劫持 |
| 模板标签别名 | 本文件的标签解析 | `<Btn/>` 解析为该类型，**优先于目录 tag**。本框架的扩展：Blazor 的别名不改变标签名 |

```xml
@using EclipseUI.Elements
@using Btn = ThirdParty.Controls.Button

<StackPanel>
    <Btn Label="hello" />
</StackPanel>
```

- **目标是目录里的已知元素/组件**（派生 `UiObject`、可见性合规）。不是 → `EUI048`，
  span 指向目标类型名；使用点不再叠加「未知标签」，同一处只有一条错。
- **别名绕过命名空间可见性**：目标所在命名空间不必 `@using`。这正是它解决重名的机制——
  `@using A` + `@using B` 都导入时同名 tag 是 `EUI016`，别名则是模板内的显式选择。
- **别名优先于目录 tag**：`@using Button = ThirdParty.Controls.Button` 之后 `<Button/>` 指第三方类型；
  未命中别名才回落到目录解析。
- **同一模板内别名只能声明一次**（重复 → `EUI048`，先声明者生效）；
  **不得与已导入的命名空间同名**（`@using Btn` + `@using Btn = …` → `EUI048`，避免落到 CS0576 指向生成文件）。
- **别名不参与命名空间可见性集合**：`CollectImports` 只收命名空间形态。否则别名会被当成命名空间
  去匹配候选，导致所有标签静默不可见。
- 词法上只支持单行、非泛型、右侧点分类型名（可带 `global::`）；`@using static`、`@using (...)`、
  尾分号、`A.B = …`、`List<string>` 都在词法层报 `EUI100` 专属消息，错误 token 吞掉整行。
- 生成形态见 spec/02 §4.18。

## 5. 字面量

### 5.1 判定与转换时机

- 属性值 token 是双引号字符串 → 字面量；是不带引号的 `{...}` → 表达式。引号内的 `{x}` 是字符串，不是表达式。
- 字面量在**编译期**按目标类型转换；生成代码直接写 C# 字面量或常量构造，运行时不解析字符串、不反射（R2）。
- 数字/布尔/枚举/TimeSpan 转换前 `Trim()`；`string` 保留原样（包括前后空格与换行）。
- 使用 `InvariantCulture`；小数点固定 `.`，不使用千分位；`EUI003` 消息给出期望格式示例。
- 无转换器的类型：字面量报 `EUI023`；✅ 2026-11-12 起第三方可通过**声明式解析器**扩展——类型标注
  `[UiLiteralParser]` 并提供 `public static T Parse(string)`，编译期只读符号校验签名（不执行用户
  程序集，R1 保留），字面量格式用特性的 `Pattern`（BCL Regex，编译期）校验，通过即生成
  `global::Ns.T.Parse("literal")`；不合规声明进 EUI026。自定义类型也可直接用 `{expression}`。

### 5.2 内置转换器

| 目标类型 | 接受的写法 | 生成的 C# | 状态 |
|---|---|---|---|
| `string` | 任意原始文本；空串合法 | C# 转义字符串字面量 | ✅ |
| `bool` | `true` / `false`（小写） | `true` / `false` | ✅ |
| `double` | 十进制/科学计数，可选符号；`1`、`8.5`、`1e-3` | `R` 格式 + `d` 后缀（`8d`） | ✅ |
| `int` | 十进制整数，可选符号；范围 `int` | 十进制字面量 | ✅ |
| `float` | 同 `double` | `R` + `f` 后缀 | ✅ C3 |
| `long` / `short` / `byte` | 十进制整数，范围检查 | `L` 后缀 / 显式窄化 | ✅ C3 |
| `decimal` | 十进制数，范围检查 | `m` 后缀 | ✅ C3 |
| `char` | 单字符或 `\n`/`\r`/`\t`/`\\`/`\"`/`\'`/`\0`/`\uXXXX` | C# 字符字面量 | ✅ C3 |
| 枚举 | 成员名，大小写敏感；不接受逗号组合/Flags | `global::Ns.Enum.Member` | ✅ C3 |
| `TimeSpan` | `250ms`、`1.5s`、`2m`、`1h`、`1d`，或 `[-][d.]hh:mm[:ss[.fffffff]]` | `new global::System.TimeSpan({ticks}L)`（编译期换算） | ✅ C3 |
| `Color` / `Thickness` / `CornerRadius` | 类型引入时定义 | — | G4 |

规则：

- 数字范围错误、格式错误、枚举成员不存在 → `EUI003`，消息带期望格式/候选成员。
- 整数不接受小数/指数；`double` 接受 `1e3`；不接受 `NaN`/`Infinity` 字面量，需要时写表达式。
- 枚举不接受 `A, B` 组合；Flags 用表达式 `{ MyFlags.A | MyFlags.B }`。
- TimeSpan 单位只允许单个：`1h30m` 不是字面量；用 `{ TimeSpan.Parse("01:30:00") }` 或 `1.5h`。
- 字面量中的 `{`/`}`/`<` 不受文本特殊字符规则影响（它们只在引号内是普通字符）。
- `[UiLiteralParser]` 类型（✅ 2026-11-12）：成员名之外的任意文本，格式由特性 `Pattern` 校验
  （不填则运行时 `Parse` 自行抛错）；`Hint` 进 EUI003 消息；`Candidates` 供 LSP 引号内补全。
  内建类型优先于解析器（解析器注册到内建键会被忽略）。
- 转换器查找键固定为目录的 `UiTypeShape.CanonicalKey`（内置类型 = C# 关键字名，
  其余 = 命名空间限定全名），**不得**用自带 `global::` 的显示类型名当键。

### 5.3 字面量与表达式的边界

- `P="{x}"` → 字符串 `{x}`；`P={x}` → 表达式 `x`。
- `P="true"` 对 `bool` 属性是字面量；`P={true}` 是表达式；两者生成结果相同。
- 字符串里需要引号/反斜杠且要求精确字符时，用表达式：`P={"a\"b"}`。
- 字面量不能被当作事件处理器（`OnClick="Foo"` → `EUI004`）；事件必须表达式。
- 字面量不能作为 `@bind-P` 的值（`@bind-Checked="true"` → `EUI037`）；双向绑定必须给可写表达式。

### 6.3 建议算法

- 未知标签/属性/事件/参数时，在**全部命名空间**里找最近名（Levenshtein ≤ 3）；
  候选超过 3 个时只列前 3。
- 候选集包括可用与不可用标签（不可用标签给出原因，避免把拼错的名字指向不可用类型）。
- 跨类别也提示（"did you mean event 'OnClick'?"）。
- 名字命中公开 CLR 属性但没有 `{Name}Property` 时，提示"未注册 StyledProperty，不参与模板"
  （`EUI002`），而不是建议改写拼写。
- 建议只做提示，不改变解析结果。

### 6.4 保留语法的诊断纪律

- 保留语法必须报 `EUI031`/`EUI029`/`EUI030`，不得退化成 `EUI001`/`EUI002`；
  具名插槽已实现（C6），其非法使用报 `EUI022`（同样不得退化成拼写建议）。
- `@bind-` 不是保留语法：目标/源非法报 `EUI040`/`EUI037`，不得退化成未知属性。
- 旧语法 `P:bind`/`P:value` 已移除（K27）：必须报 `EUI046`（Error）+ 改写建议，不得静默当普通属性名。
- 任何"看似可用、运行时才炸"的降级都不允许；诊断缺失视为实现缺陷。

### A.1 `TodoList.ui`

```xml
<StackPanel Gap="8">
    <TextBlock FontSize="24">待办清单</TextBlock>

```

### A.2 `TodoItem.cs`

```csharp
namespace Examples;

public sealed class TodoItem
{
    public int Id { get; init; }          // 普通属性：用于 Key
    public string Title { get; set; } = "";
    public bool Done { get; set; }
}
```

### A.3 `TodoList.cs`（code-behind）

```csharp
using System.Collections.Generic;
using EclipseUI;

namespace Examples;

public partial class TodoList
{
    public List<TodoItem> Tasks { get; } = new()
    {
        new() { Id = 1, Title = "读 01 语法规范" },
        new() { Id = 2, Title = "补测试用例" },
    };

    public bool ShowCount { get; set; }

    private int _nextId = 3;

    private void AddTask()
    {
        var id = _nextId++;
        Tasks.Add(new TodoItem { Id = id, Title = $"任务 {id}" });
    }
}
```

### A.4 语义对照

| 写法 | 语义 | 依据 |
|---|---|---|
| `Gap="8"` / `FontSize="24"` | 编译期字面量转换，一次性赋值 | §5 |
| `@bind-Checked={ShowCount}` | 双向绑定；源值胜出；目标变化回写源并 `Invalidate()` | §4.5 |
| `@if (ShowCount) { ... }` | 每次渲染重算条件；分支切换销毁/重建 | §4.10 |
| `共 {Tasks.Count} 项` | 动态文本；每次渲染重设整段字符串 | §4.9 |
| `@foreach (var t in Tasks)` | 任意 `IEnumerable<T>`；每次刷新重新枚举 | §4.11 |
| `Key={t.Id}` | 条目身份；Key 相等且 item 引用相等才复用 | §4.12 |
| `@bind-Checked={t.Done}` | item 可写属性双向；回写 item 并失效组件 | §4.5 / §4.11 |
| `{t.Title}` | item 文本；复用条目每次刷新重跑 | §4.12 |
| `OnClick={() => AddTask()}` | 初始化时 `AddHandler`；处理器后自动 `Invalidate()` | §4.13 |

`Tasks.Add` 发生在 `OnClick` 处理器内，处理器返回后自动失效，因此列表与计数会在同一帧更新；
后台线程修改普通状态后应显式投递UI任务并失效；安装UI同步上下文时，await续体经宿主批量排空自动失效。

### B.1 属性形态
