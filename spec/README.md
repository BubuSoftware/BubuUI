## 权威关系

1. **语法**：`spec/01` 取代 [design/03](../design/03-template-engine.md) §3.1–§3.5 的规范地位。
   design/03 的 §3.5.3（v3 台账 D1–D41）、§3.5.4（v4 台账 D42–D88）与附录是代码差距的活记录。
2. **生成代码**：`spec/02` 取代 design/03 §3.6 与 [design/14](../design/14-control-template-contract.md) §14.8 的规范地位；
   design/14 §14.8 已标记为 v3 历史。
3. **反应式/绑定**：`spec/03` 是规范正本。[design/15](../design/15-state-and-reactivity.md) 已停止（v3 历史，含 `[UiState]`/`UiWatch`/依赖分析）。
4. **控件/组件元数据**：在 `spec/04` 迁移前，以 design/14 为准（其反应式/生成形态条款由 spec/02、spec/03 取代）；`spec/01` 只定义模板侧如何使用。
5. **历史记录**：design/03、design/14、design/15 的修订记录与决策记录不重写；新决策写入本目录对应文档的变更记录。
6. **决策权威位置**：所有架构/语法/范围/排期决策以 [spec/02 §14 关键决策表](./02-generated-code-contract.md) 为准，
   并同步受影响的规范条目与偏差台账（spec/01 §6.2/§7.1、design/03 §3.5.4、spec/02 §12、design/09）。
   AI 会话记忆与聊天记录只作留痕，不构成决策落地；决策未进项目文档视为未落地。
7. **决策与实施分离**：K23 已定但代码未实现的语法，目标口径写在 spec/01 §1.5、差距写在 spec/02 §12（D85–D88）；
   本文其余章节仍描述当前 v2 实现并显式标注「当前实现」，不得把目标语法写成已生效。

## v4 换轨记录

v1 规范的依赖订阅模型（`[UiState]`/`Signal<T>`/`UiWatch`/依赖分析）已整体废止，换为组件级失效重算：

| # | 维度 | v1（依赖订阅） | v2（v4 失效重算） |
|---|---|---|---|
| V1 | 反应式单位 | 每个绑定点的定向 updater + 路径订阅 | 组件 `Invalidate()` → `Render()` 重算根级动态表达式 |
| V2 | 状态 | `[UiState]` 源生成器 + 可观察 partial 属性 | 普通 CLR 字段/属性/类，类型不受限 |
| V3 | 块 | 块自动订阅集合/条件信号 | `SetContent`/`SetTemplate` 只登记，生成代码显式 `Refresh()` |
| V4 | 双向 | `:bind` + `Signal<T>` 右侧 | `@bind-P`（可写左值）+ 组件 `{P}Changed` 回调 |
| V5 | 组件参数 | 可观察参数 / `Signal<T>` 参数 | 普通属性 + 相等保护推送 + 子 `Invalidate()` |
| V6 | 诊断 | EUI014/EUI034–EUI036/EUI038–EUI039/EUI041–EUI042/EUI044 | 停用上述码；新增 EUI045；下一码 EUI046 |
| V7 | 历史文档 | design/15 为权威 | design/15 停止；design/03 §3.5.3 为 v3 台账，§3.5.4 为 v4 台账 |
